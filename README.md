# Empire Bysonic Computing

A static website for Empire Bysonic Computing, a computer repair, maintenance, upgrade, quotation, and sales business serving the Southern Suburbs, Cape Town, Western Cape.

## Features

- Laptop and desktop repair information
- Hardware diagnostics and stress-testing services
- RAM and SSD upgrade information
- Screen, bezel, charging-port, and component repair services
- Repair booking and quotation pages
- Moderated community device-sale submissions and approved listings (Supabase setup required)
- SnapScan payment-link button
- Animated service and social-media buttons
- Tawk.to live chat on the homepage and journal articles
- Local customer-support chatbot with prewritten responses
- Responsive layout for desktop and mobile screens
- SEO metadata and local-business structured data

## Main Files

- `index.html` - Published homepage
- `website.html` - Alternate full website page
- `style.css` - Shared styling and LED effects

## SnapScan Payment Link

The payment page contains a placeholder payment URL. Replace it in `Payment.html` with the real payment link created in the SnapScan merchant dashboard:

```javascript
const snapScanPaymentLink = 'YOUR_REAL_SNAPSCAN_PAYMENT_LINK';
```

The payment URL should be generated by the business owner through the SnapScan merchant account. Never place merchant passwords, secret keys, or private credentials in this repository.

## Run Locally

Because this is a static website, informational pages can be opened directly in a browser by opening `index.html`. The support chatbot uses prewritten browser responses, so it needs no Node server, API key, Render account, or paid service. The community marketplace needs an HTTP server (such as VS Code Live Server) and the Supabase setup below; it is intentionally disabled when project settings are blank or the page is opened as a local file.

For example, use the VS Code Live Server extension or any simple static-file server.

## Community Marketplace Setup

The sale form on `index.html` and the alternate `website.html` uses Supabase Edge Functions, Postgres, and private Storage. Listings stay pending until an administrator approves them. Seller WhatsApp numbers are private, required contact consent is recorded, uploaded images are limited to JPEG/PNG/WebP up to 4 MB, and submissions are limited to three per IP-hash per hour. Public listing queries return approved item details only.

The source code is ready, but the feature remains disabled until a Supabase project and Meta WhatsApp Business Cloud API are configured. The checked-in `marketplace-config.js` intentionally has blank settings. Set its `supabaseUrl` and public `supabaseAnonKey` from the Supabase project dashboard. The anon key is designed to be public; never put a service-role key, WhatsApp token, App Secret, or webhook verify token in browser code.

1. Create a Supabase project and install the Supabase CLI.
2. From this repository, link the project and apply the marketplace migration:

   ```powershell
   supabase link --project-ref YOUR_PROJECT_REF
   supabase db push
   ```

3. In Supabase Dashboard > Edge Functions > Secrets, configure `ALLOWED_ORIGINS` to exact origins (no trailing slash), for example `https://empire-bysonic-computing.github.io,http://127.0.0.1:5500,http://localhost:5500`. Also set a randomly generated `SUBMISSION_IP_HMAC_SECRET`. The Edge Functions use the project's standard `SUPABASE_URL`, `SUPABASE_ANON_KEY`, and `SUPABASE_SERVICE_ROLE_KEY` runtime secrets.
4. Deploy `submit-marketplace-listing`, `public-marketplace-listings`, and `whatsapp-marketplace-webhook`:

   ```powershell
   supabase functions deploy submit-marketplace-listing
   supabase functions deploy public-marketplace-listings
   supabase functions deploy whatsapp-marketplace-webhook
   ```

5. In Meta's WhatsApp Business Platform setup, register the business sender number, create a long-lived access token, subscribe the app to the `messages` webhook field, and create an approved message template named in `WHATSAPP_ALERT_TEMPLATE`. The template must be in `WHATSAPP_ALERT_TEMPLATE_LANGUAGE` and contain three body placeholders in this order: listing name, price, listing ID. The owner alert/command recipient is configured separately as the server-side `WHATSAPP_OWNER_PHONE`; leave it private and use a WhatsApp number you control that can receive alerts. It should be separate from the registered business sender number, and should first opt in by messaging that business number. Set `WHATSAPP_ACCESS_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`, current supported `WHATSAPP_API_VERSION`, `WHATSAPP_OWNER_PHONE`, `WHATSAPP_ALERT_TEMPLATE`, `WHATSAPP_ALERT_TEMPLATE_LANGUAGE`, `WHATSAPP_APP_SECRET`, and a unique `WHATSAPP_VERIFY_TOKEN` as Supabase secrets. Set the Meta callback URL to `https://YOUR_PROJECT_REF.supabase.co/functions/v1/whatsapp-marketplace-webhook` and use the same verify token in Meta and Supabase.
6. Set the public project URL and anon key in `marketplace-config.js`, then publish the changed site files. Test with a small listing before public launch.

After setup, send `APPROVE <listing-id>` or `REJECT <listing-id>` from the configured owner WhatsApp number to the business Cloud API number. To contact a consenting seller for an approved listing, send `REPLY <listing-id> <message>`. WhatsApp may reject free-form replies outside its 24-hour service window; in that case the seller must message first or the business must use an approved WhatsApp template. Keep normal seller/customer conversation in WhatsApp; no custom `.exe` is needed or created.

Review and delete rejected/old submissions periodically to limit retention of sellers' private contact information. Supabase and Meta accounts, project secrets, and WhatsApp template approval must be controlled by the site owner; do not send private keys through chat or commit them.
